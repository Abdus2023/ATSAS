## 1. The Deeper System Model

The behavioral test matrix (`AAI-001`..`AAI-034`, `P-001`..`P-008`) demonstrates that an assured agentic system is **not** a one-step mapping (`request → skill → answer`). It is a 6-stage state-transition pipeline in which **every transition requires an observable predicate**:

```text
                    ┌───────────────┐
                    │    REQUEST    │
                    └───────┬───────┘
                            │
                            ▼
                    ┌───────────────┐
                    │    INTAKE     │
                    │ authority     │
                    │ requested     │
                    │ scope         │
                    └───────┬───────┘
                            │
                       ADMISSION
                            │
                            ▼
                    ┌───────────────┐
                    │    EXECUTE    │
                    │ actual actor  │
                    │ actual paths  │
                    │ actual cmds   │
                    └───────┬───────┘
                            │
                            ▼
                    ┌───────────────┐
                    │    VERIFY     │
                    │ snapshot      │
                    │ command       │
                    │ result        │
                    └───────┬───────┘
                            │
                            ▼
                    ┌───────────────┐
                    │    EVIDENCE   │
                    │ provenance    │
                    │ artifacts     │
                    │ timestamps    │
                    └───────┬───────┘
                            │
                            ▼
                    ┌───────────────┐
                    │   COMPLETE    │
                    │ acceptance    │
                    │ criteria      │
                    └───────────────┘
```

### Fundamental Non-Equivalences

| State / Predicate | Is NOT Equivalent To | Why (`AAI` Invariant & Test Case) |
|---|---|---|
| `AUTHORIZED` | *"The agent was capable of doing it"* | Tool access in sandbox ≠ task authority (`AAI-001`, `AAI-002`, `AAI-004`). |
| `ADMITTED` | *"The path was touched during work or generated by a build"* | Touching a neighboring file (`AAI-003`), editing `README.md` (`AAI-005`), or emitting `dist/` (`AAI-006`) ≠ scope admission. |
| `EXECUTED` | `PASSED` | Declaring a script (`AAI-018`) ≠ running it; running a command with missing or non-zero exit code (`AAI-025`) ≠ passing (`AAI-004`, `AAI-005`). |
| `PASSED` | `VERIFIED` | A passing process on 1 test file (`AAI-024`), modified tests (`AAI-026`), or typecheck only (`AAI-029`) ≠ verified repository claim (`AAI-007`). |
| `VERIFIED` | `COMPLETABLE` | Passing tests with an out-of-scope file (`AAI-032`), stale snapshot (`AAI-033`), or an unmet mandatory criterion (`AAI-034`) ≠ task completable (`AAI-009`). |

### Non-Boolean Failure Transitions

Failure transitions must **never** be collapsed into a single `PASS / FAIL` boolean:

```text
PROPOSED
    ├── vague / undefined scope      → BLOCKED           (AAI-001)
    ├── approval policy unsatisfied  → BLOCKED           (AAI-004)
    └── read-only request            → INSPECT_ONLY      (AAI-002)

AUTHORIZED
    ├── scope failure                → REJECTED          (AAI-003, AAI-005, AAI-008, AAI-032)
    ├── authorization loss / change  → BLOCKED           (P-008)
    └── execution failure            → EXECUTION_FAILED  (AAI-005)

EXECUTED
    ├── no observation               → NOT_OBSERVABLE    (AAI-013, P-003, P-006, P-007)
    ├── result unavailable           → UNVERIFIED        (AAI-022, AAI-025, AAI-027)
    └── stale snapshot               → EVIDENCE_STALE    (AAI-020, AAI-023)

VERIFIED
    ├── snapshot mismatch            → EVIDENCE_MISMATCH (AAI-028, AAI-033, P-004)
    └── missing criterion            → INCOMPLETE        (AAI-031, AAI-034)
```

### Transition Predicates

| Transition | Source → Target | Required Observable Predicate |
|---|---|---|
| **Authority Check** | `PROPOSED → AUTHORIZED` | Explicit user request + satisfied repository governance policy + explicit mutation mode (`INSPECT_ONLY` vs `MUTATION_AUTHORIZED`). |
| **Scope / Admission** | `AUTHORIZED → ADMITTED` | `∀ path ∈ executed_diff(base, head): path ∈ AUTHORIZED_SCOPE`, with `PREEXISTING` and `GENERATED` paths separated and policy-checked. |
| **Action** | `ADMITTED → EXECUTED` | Concrete process invocation or file operation recorded with actor identity, `executed_command`, timestamps, and observed `exit_code`. |
| **Verification** | `EXECUTED → VERIFIED` | `exit_code == 0` observed at `snapshot == HEAD`, full target scope covered, and verification surface integrity preserved. |
| **Evidence Bind** | `VERIFIED → EVIDENCED` | Immutable `ArenaEvidenceReceipt` binding claim, `subject_sha == evidence_sha`, `declared_command`, `executed_command`, `execution_evidence`, environment, and detector metadata. |
| **Acceptance Gate** | `EVIDENCED → COMPLETABLE` | `∀ mandatory_criterion ∈ ClaimMatrix`: backed by a valid, non-stale `EVIDENCED` receipt at current `HEAD` with zero `BLOCKED` or `REJECTED` gates. |

## 3. Canonical Evidence Vocabulary (Four Orthogonal State Axes)

To prevent semantic collapse, the assurance system maintains **four distinct state enums**. Implementations and schemas must never merge these four axes into one flat `status` enum.

### Axis 1: Observation States (`observation_state`)
Describes **how** a proposition entered the assurance system:
- `OBSERVED` — Directly witnessed via deterministic tool output, file hash, or process exit code in the current environment.
- `DERIVED` — Deterministically computed from `OBSERVED` inputs via a reproducible rule or script.
- `INFERRED` — Heuristic or pattern-matched conclusion requiring human/policy confirmation (e.g., `SUSPECTED` entropy hit).
- `CLAIMED` — Asserted in agent prose or user prompt without direct observation (`CLAIM_ONLY`).
- `UNKNOWN` — Epistemic state has not yet been determined.
- `NOT_OBSERVABLE` — The environment lacks the tool, lockfile, network access, or runtime required to observe the target property (`P-003`, `P-006`, `P-007`).

### Axis 2: Execution States (`execution_state`)
Describes **what happened** at the operational / process layer:
- `NOT_REQUESTED` — Capability is declared/configured (`TEST_DECLARED`, `CI_CONFIGURED`) but execution was not attempted.
- `AUTHORIZED` — Action has been granted authority under the current request and repo policy.
- `ADMITTED` — Target paths/commands passed scope admission checks.
- `STARTED` — Process or action began execution.
- `EXECUTED` — Process completed and produced an observable exit code and output streams.
- `EXECUTION_FAILED` — Process exited non-zero, crashed, or timed out.
- `CANCELLED` — Execution was aborted before completion.

### Axis 3: Verification States (`verification_state`)
Describes **whether the evidence validates the specific claim** at the target snapshot:
- `NOT_VERIFIED` — No verification check has been bound to the claim.
- `VERIFIED` — Claim is supported by fresh, scope-matched, snapshot-matched `OBSERVED` evidence.
- `STALE` — Evidence was captured at a prior commit or prior working-tree state (`AAI-020`, `AAI-023`).
- `MISMATCH` — Receipt `evidence_sha` disagrees with `subject_sha` (`AAI-028`) or local vs. CI snapshots diverge (`AAI-033`).
- `PARTIAL` — Evidence covers only a subset of the claim (single test file `AAI-024`, missing exit code `AAI-025`, single scanner `AAI-012`, typecheck-only `AAI-029`, manifest without lockfile `AAI-013`).
- `UNVERIFIABLE` — Verification cannot be performed due to `NOT_OBSERVABLE` prerequisites or modified verification surface (`AAI-026`).

### Axis 4: Completion States (`completion_state`)
Describes **terminal task-gate eligibility** evaluated by `arena-completion-gate`:
- `COMPLETABLE` — Every mandatory criterion in the Claim Matrix is `VERIFIED` and `EVIDENCED` at `HEAD`, with `AUTHORIZED` + `ADMITTED` scope.
- `INCOMPLETE` — One or more mandatory acceptance criteria lack sufficient evidence (`AAI-031`, `AAI-034`).
- `BLOCKED` — Task cannot proceed or complete due to missing authority (`AAI-001`, `AAI-004`), scope violation (`AAI-032`), or mid-task authority invalidation (`P-008`).
- `REJECTED` — Unauthorized execution (`AAI-001`), out-of-scope mutation (`AAI-005`, `AAI-008`), or illicit audit self-remediation (`P-002`) occurred.
- `UNVERIFIED` — Completion was claimed in prose (`P-001`, `P-005`) or receipt (`AAI-027`) without underlying verification evidence.
